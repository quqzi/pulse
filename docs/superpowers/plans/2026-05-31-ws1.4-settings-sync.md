# WS1.4 — Settings Sync + Single-Source Cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sync an authenticated user's settings across devices via a new `user_settings` table, give the exam date one home (`settings.examDate`), and unify the history window (90→112 days) so the sessions load and the Journey heatmap agree — for both guest and auth.

**Architecture:** Settings is a single per-user object (not a `repository<T>` array entity), so it gets its own sync module. Guest persistence stays in `settings.ts` (localStorage), guarded to guest-only. A new `data/settingsSync.ts` owns the auth path: hydrate-on-login from `user_settings` (merge over `defaults()`, applied through a suppress-guarded `set` so it doesn't echo back as a write), then debounce-upsert on change. The divergent `Settings` interface is reconciled FIRST (delete the stale `types.ts` copy, unify on the `stores/settings.ts` shape that has `examDate`). A shared `HISTORY_DAYS` constant drives both the sessions window and the heatmap geometry.

**Tech Stack:** SvelteKit 2, TypeScript, Supabase (Postgres + Auth, JSONB), Vitest, Vite.

**Source of truth:** roadmap spec `docs/superpowers/specs/2026-05-29-pulse-roadmap-and-foundation-design.md` §4.2 / §4.3 (gaps G10, G11) + §4.6 acceptance.

- [ ] **Step 6: Create `settingsSync.ts`**

Create `src/lib/data/settingsSync.ts`:
```ts
import { get } from 'svelte/store';
import { browser } from '$app/environment';
import { settings, defaults, type Settings } from '$lib/stores/settings';
import { authCtx } from '$lib/data/authctx';
import { supabase } from '$lib/supabase';

/** Pure: overlay a remote settings blob onto a fresh defaults() object. */
export function mergeRemote(remote: Partial<Settings> | null | undefined): Settings {
  return { ...defaults(), ...(remote ?? {}) };
}

let suppress = false;            // true while applying a remote value (don't persist the echo)
let hydratedUserId: string | null = null;
let debounceTimer: ReturnType<typeof setTimeout> | null = null;

function loadGuestSettings(): Settings {
  try {
    const raw = localStorage.getItem('pulse_settings');
    return raw ? mergeRemote(JSON.parse(raw)) : defaults();
  } catch { return defaults(); }
}

async function hydrate(userId: string): Promise<void> {
  const { data, error } = await supabase
    .from('user_settings').select('settings').eq('user_id', userId).maybeSingle();
  if (error) return;             // read failure → leave store as-is (parity with repo reads)
  suppress = true;
  settings.set(mergeRemote(data?.settings as Partial<Settings> | undefined));
  suppress = false;
  hydratedUserId = userId;
}

function upsertDebounced(userId: string, val: Settings): void {
  if (debounceTimer) clearTimeout(debounceTimer);
  debounceTimer = setTimeout(() => {
    void supabase.from('user_settings').upsert(
      { user_id: userId, settings: val, updated_at: new Date().toISOString() },
      { onConflict: 'user_id' },
    );
  }, 600);
}

/** Wire settings persistence/hydration to auth. Call once, client-side, from the root layout. */
export function initSettingsSync(): void {
  if (!browser) return;

  authCtx.subscribe(ctx => {
    if (ctx.mode === 'authenticated' && ctx.userId && hydratedUserId !== ctx.userId) {
      void hydrate(ctx.userId);
    } else if (ctx.mode === 'guest' && hydratedUserId !== null) {
      // logged out: drop the synced user and restore this device's guest settings
      hydratedUserId = null;
      suppress = true;
      settings.set(loadGuestSettings());
      suppress = false;
    }
  });

  settings.subscribe(val => {
    if (suppress) return;
    const { userId, mode } = get(authCtx);
    if (mode === 'authenticated' && hydratedUserId === userId) {
      upsertDebounced(userId, val);
    }
    // guest persistence stays in settings.ts; auth-but-not-yet-hydrated is intentionally skipped
  });
}
```

## Notes / Decisions (surface in the PR)

- **First login with no DB row → `defaults()`**, NOT the device's guest settings (consistent with how entity data does not carry guest→account). A user who themed as a guest then logs in for the first time sees defaults until they re-set.
- **Guest sessions are now windowed to 112 days** (today they're uncapped). Older localStorage sessions are retained on disk but not loaded into the view — intended parity with auth.
- **Auth-mode cross-device sync is not browser-verifiable this session** (needs a real logged-in account + second device). It's covered by the `mergeRemote` unit test, the type-check, and review. The echo-guard (`suppress`) and per-user `hydrated` gate are the correctness-critical pieces to review closely.
- **localStorage namespace:** settings intentionally keeps its existing `pulse_settings` key (has migration logic for old `designTheme`); not renamed to `pulse.settings` to avoid wiping guest settings. The broader `pulse.schemaVersion` namespace idea from spec §4.3 is deferred (not required for the three WS1.4 goals).
