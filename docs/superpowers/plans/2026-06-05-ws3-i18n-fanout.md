# WS3 Thai i18n Fan-out Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend the WS3 Thai i18n pilot (nav + dashboard) across the remaining ~11 app pages so the entire app renders in Thai when `lang === 'th'`.

**Architecture:** Reuse the established pilot pattern unchanged — `$t.section.key` from the dict-as-store (`src/lib/i18n/{en,th}.ts`, `t = derived(settings)`), dates/numbers via `$fmt` (Gregorian-forced Thai locale). Two kinds of page: **wire-only** (en/th keys already exist from the pilot — just swap hardcoded strings for `$t`) and **keys+wire** (author a new en+th namespace, then wire). The existing parity guard test (`src/lib/i18n/i18n.test.ts`) mechanically enforces en/th key+type parity, so a missing or mistyped key fails CI.

**Tech Stack:** SvelteKit 2 + Svelte 4 idiom, TypeScript, `Intl.DateTimeFormat`/`NumberFormat` via the `fmt` store.

---

## Conventions (apply to every page task)

These are the invariants every task below follows. Read once; they are not repeated per task.

- **Import:** add `import { t } from '$lib/i18n';` (add `, fmt` only if the page formats dates/numbers).
- **Usage:** `$t.section.key` in templates; function-valued keys for interpolation, e.g. `$t.tasks.seeMore(n)`. Dates: `$fmt.date(iso, opts)`. Numbers: `$fmt.num(n, opts)`.
- **`t`-shadow rule:** this codebase uses `t` as a loop/lambda variable (`{#each xs as t}`, `xs.find(t => …)`). The `$t` store import collides with it. **Rename every local `t` to `tp`** in any component you convert (see pilot commits `2202377`). After converting, grep the file for `\bt\b` as an identifier to confirm none remain.
- **No new hardcoded strings:** every user-visible English string (visible text, `placeholder=`, `aria-label=`, `title=`, toast messages) must come from `$t`. Pluralization/interpolation → function-valued key.
- **Keys live in BOTH `en.ts` and `th.ts`** with identical shape; `en.ts` is the canonical `I18n` type, `th.ts` is typed `: I18n`.
- **Thai voice:** casual-friendly (per project decision). Draft Thai, flag for user review at the checkpoint task.
- **Verify loop per page:** `npm run check` (0 errors) → `npx vitest run` (parity passes) → browser-verify the page in Thai on a worktree dev server **after `npm install` in the worktree** (fs.allow alone gives corrupt renders — see memory note) → commit.
- **Commit message:** `feat(i18n): wire <page> to $t`.

## File Structure

- `src/lib/i18n/en.ts` — add new namespaces: `analytics`, `schedule`, `scores`, `journey`, `exam`. Extend `common` as shared strings emerge.
- `src/lib/i18n/th.ts` — mirror every addition.
- `src/routes/(app)/<page>/+page.svelte` — wire each page (11 files).
- `src/lib/components/**` — feature components rendered by these pages that contain hardcoded strings (converted alongside their owning page).
- No new files, no engine/store changes. Pure presentation layer.

## Self-Review

**Spec coverage:** The pilot established the pattern; this plan covers all remaining routes from the survey — timer, tasks, subjects (list/detail/templates), settings body, onboarding body (Batch 1, keys exist); analytics, schedule, scores, journey, exam (Batch 2, new namespaces); insights stub + straggler sweep (Task 12); plus translation review (Task 13) and finish (Task 14). No route from `src/routes/(app)/` is left unaddressed.

**Placeholder scan:** Per-page string enumeration is deferred into each task's Step 1 ("read the page, list visible strings") rather than pre-listed — deliberate for ~200+ strings across 11 files, and made safe by the existing parity guard test which fails on any en/th key mismatch. Each task names the exact files, the exact namespace, the exact verify commands, and the exact commit message.

**Type consistency:** All new namespaces are added to `en.ts` first (canonical `I18n` type) and mirrored in `th.ts` (typed `: I18n`), so `npm run check` enforces shape consistency. Function-valued keys (interpolation) follow the pilot's signature style `(n: number) => \`…${n}…\``.

**Ordering risk:** Batch 1 ships fastest (no translation authoring). Batch 2 front-loads Thai drafting; the single review checkpoint (Task 13) batches all Thai for one user pass rather than interrupting every page.
