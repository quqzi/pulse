# WS2.2 — Mobile Layouts (Scores / Subjects / Dashboard) — Design

**Date:** 2026-06-03
**Status:** Approved (brainstorm), pending implementation plan
**Parent:** WS2 (multi-device & interaction correctness). Follows WS2.1a–c (schedule touch drag, schedule mobile layout, anchored popovers, mobile a11y touch targets).
**Source:** mobile audit (2026-06-03) + page read-through. The audit found no overflow bugs, but several actions are reachable only on `:hover`, which never fires on touch.

---

## 1. Problem

Three pages have touch-unfriendly interaction, the worst being **actions hidden behind `:hover`** — invisible and untappable on a phone:

| Page | Issue | Severity |
|---|---|---|
| **Scores** | `.item-actions` (Edit/Delete) are `opacity:0`, revealed only on row `:hover`. On touch you **cannot edit or delete a score at all.** Rows also pack chip + name + date + notes + fraction + % + sparkline + (hidden) actions onto one line. | Functional + density |
| **Subjects** | The per-tile `.edit-btn` pencil is `opacity:0` until `.tile-wrapper:hover`. On touch you **cannot edit a subject** (name/symbol/colour/delete). Header crowds three controls (Templates link, "Save as template" button, "+") around the title. | Functional + crowding |
| **Dashboard** | Already mobile-first (centered single column, tiles tap to open detail — no hover trap). | Minor / verify only |

## 2. Goal

Every action that exists on desktop is reachable on touch, discoverably; the cramped Scores row and crowded Subjects header are decongested. **Desktop behaviour is unchanged** (it keeps its working hover affordances).

## 3. Decisions (from brainstorm)

- **Interaction pattern: tap the item → open a bottom action sheet** (option B). Chosen over always-visible inline buttons (keeps rows clean, preserves the sparkline) and over swipe-to-reveal (YAGNI: most engineering, undiscoverable, fights scroll).
- **Reuse the existing `BottomSheet.svelte`** (built in WS2.1) as the action sheet everywhere — swipe-down dismiss, Esc, backdrop click, reduced-motion already handled.
- **Subjects edit moves into the subject detail page** (not an always-visible tile pencil), since tapping a tile already opens the detail page — the detail page is the natural home for "act on this subject."
- **Fix all four audit items** (A hover actions, B subjects header, C scores density, D dashboard verify).

## 4. Non-goals (YAGNI)

- No swipe gestures, no long-press menus.
- No schema/data/store changes; no new repo methods.
- No redesign of `SubjectTile`, `HeroCard`, or the score row's visual identity beyond removing the hidden action column.
- No desktop **layout** changes, and no desktop capability is lost. Two intentional cross-device behaviour tweaks are in scope: (1) Subjects "edit" relocates from the grid hover pencil to the detail-page Edit button (applies on desktop too — a deliberate consolidation, edit is still fully reachable); (2) Scores rows become additionally tappable while desktop keeps its existing hover Edit/Delete buttons. No other desktop interaction changes.
- No change to the existing add/edit *forms* (`ScoreForm`, the subjects edit sheet) — only how they're reached.

## 5. Design

### 5.1 Scores — tap row → action sheet  *(fixes A + C)*
`scores/+page.svelte`:
- Make each `.score-item` a button-semantics row: `role="button"`, `tabindex="0"`, `on:click` + `on:keydown` (Enter/Space) → set `actionScore = score; actionSheetOpen = true`. Add an `:active` press state so it reads as tappable. The row is tappable on **all** widths (harmless on desktop).
- **Density / touch fix for the hover column:** keep the `.item-actions` (Edit/Delete) column for desktop, but (a) gate its hover-reveal behind `@media (hover: hover) and (pointer: fine)` so only true-pointer devices show it, and (b) set `.item-actions { display: none }` inside `@media (hover: none)` (touch) so on a phone the column is **removed from layout entirely** — freeing the row space (density complaint resolved, **sparkline retained**) and ensuring it can never be a dead, untappable invisible control on touch.
- Add a `<BottomSheet bind:open={actionSheetOpen} on:close=…>` containing a header (`{subjectName} · {formatDate}`) and two ≥44px action buttons:
  - **Edit** → `openEdit(actionScore)` (existing flow → `ScoreForm`), close sheet.
  - **Delete** → `promptDeleteScore(actionScore)` (existing flow → `ConfirmDialog`), close sheet.
- `openEdit` / `promptDeleteScore` / `handleSave` are unchanged; the sheet is only a new entry point.
- **Net result by device:** touch → tap row → sheet (no hover column); desktop → hover buttons as today **plus** the row is also tappable. Desktop's existing affordance is preserved (honoring "no desktop behaviour change"); touch gains a reachable, discoverable path.

### 5.2 Subjects — edit into the detail page  *(fixes A)*
- `subjects/+page.svelte`: **delete** the `.edit-btn` pencil and its `.tile-wrapper:hover` CSS from the grid. Tile-tap continues to `goto('/subjects/{id}')` (unchanged). The grid no longer has any hover-only control. (The `.due-badge` stays — it's display-only.)
- `subjects/[id]/+page.svelte`: add an always-visible **Edit** button in `.page-header` (right side, opposite the back button). It opens the same edit sheet markup currently in `subjects/+page.svelte` (Name / Symbol / Colour / Cancel / Save / Delete).
  - **Implementation note:** the edit sheet + its state (`sheetOpen`, `sheetName`, `sheetSymbol`, `sheetColor`, `saveSubject`, `promptDeleteSubject`, `doDeleteSubject`, the `ConfirmDialog`) currently live in `subjects/+page.svelte`. To put edit on the detail page without duplicating, **extract the subject edit sheet into a reusable component** `src/lib/components/subjects/SubjectEditSheet.svelte` (props: `subject: Subject | null`; events: `save`, `delete`). Both the list page (for the "+" add flow) and the detail page (for edit) mount it. This keeps one source of truth for the form.
  - Add flow on the list page (`openAdd` → `SubjectEditSheet` with `subject={null}`) is preserved.

### 5.3 Subjects header — decongest  *(fixes B)*
`subjects/+page.svelte` header keeps: title, **Templates** link, **"+"** add button. **"Save as template"** moves into a small **"⋯" overflow button** (next to "+") that opens a `BottomSheet` with a single "Save current subjects as template" action (calls the existing `saveCurrentAsTemplate`). The overflow button only renders when `$subjects.length > 0` (same condition the button has today).

### 5.4 Dashboard — verify only  *(D)*
No structural change. During verification, confirm on a phone that sections stack cleanly, the subject grid reflows (4→3 cols ≤360px), and all controls are tappable. Only adjust spacing if something is visibly off.

## 7. Testing

No new unit tests (interaction/CSS + a component extraction with identical behaviour). **Browser / mobile-emulation** verification on an iPhone viewport:
- **Scores:** tap a row → action sheet opens; Edit → ScoreForm prefilled; Delete → ConfirmDialog → row removed. Sheet dismisses via swipe-down, backdrop, Esc.
- **Subjects:** grid has no hover-only control; tap tile → detail page; detail **Edit** → sheet → Save persists, Delete (via ConfirmDialog) cascades and returns to `/subjects`. Add ("+") still works from the list. "⋯" → sheet → "Save as template" creates a template.
- **Dashboard:** sections stack, grid reflows, controls tappable.
- **Desktop (≥768px):** no regression — Scores sheet still works, Subjects add/edit/delete still work, nothing visually broken.
- `npm run check` → 0 errors; `vitest run` → existing suite still green.
