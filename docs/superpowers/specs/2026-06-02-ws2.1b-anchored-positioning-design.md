# WS2.1b — Anchored Block Popovers — Design

**Date:** 2026-06-02
**Status:** Approved (brainstorm), pending implementation plan
**Parent:** WS2.1 (interaction correctness) §5.2, §7.2 — `docs/superpowers/specs/2026-05-29-pulse-roadmap-and-foundation-design.md` / `2026-06-02-ws2-multi-device-design.md`.
**Builds on:** WS2.1a (schedule touch drag) and the schedule mobile layout — both on `master`.

---

## 1. Problem

Trigger-anchored popovers use static offsets and overflow the viewport near a screen edge. An **audit of every floating element** found that only **two** are actually trigger-anchored (and therefore clip); the rest are centered modals or fixed overlays that don't have the edge-clipping bug:

| Element | Positioning | Trigger-anchored / clips? |
|---|---|---|
| **CalBlock edit popover** (`.block-popover`, `CalBlock.svelte`) | `position: absolute; top: calc(100% + 6px); left: 0` | **Yes** — overflows the right edge for blocks in later days |
| **Create `BlockPopover`** (placed by `WeekGrid.svelte`) | inline `position: absolute; left: 0; width: 240px` | **Yes** |
| `ConfirmDialog` | `fixed; inset: 0`, centered | No (centered modal) |
| `MoreDrawer` | `fixed` left drawer | No |
| `Toaster` | `fixed`, bottom-center | No |
| `QuickLog` / `ScoreForm` | modal / native `<select>` | No (browser-positioned) |

## 2. Goal

The two calendar block popovers stay **fully on-screen** at any anchor position — flipping vertically when there's no room below, and shifting horizontally to stay within the viewport with a gutter — on desktop and phone alike. No regression to the modals/overlays.

## 3. Non-goals (YAGNI)

- No changes to ConfirmDialog / MoreDrawer / Toaster / QuickLog / ScoreForm — the audit confirms they don't clip.
- **No bottom-sheet collapse on mobile** for these popovers (chosen: one render path — flip/clamp everywhere). A sheet variant can be a later polish.
- No broader floating-UI system beyond the reusable action.

## 4. Decisions (from brainstorm)

- **Positioning engine: `@floating-ui/dom`** (the WS2 decision), wrapped in a thin Svelte action so it's swappable.
- **Flip/clamp on all viewport sizes** — a single render path; the popover always anchors to the block but never leaves the viewport.

## 5. Design

### 5.1 `src/lib/actions/anchored.ts` (new)
A Svelte `use:` action applied to the floating element.

- **Options:** `{ anchor: HTMLElement; placement?: Placement; gutter?: number }` (default `placement: 'bottom-start'`, `gutter: 6`).
- **Behavior:** runs `computePosition(anchor, node, { strategy: 'fixed', placement, middleware: [offset(gutter), flip(), shift({ padding: 8 })] })` and applies the resulting `left`/`top` to `node.style` (with `position: fixed`). `flip()` flips placement when there's no room; `shift({ padding: 8 })` keeps the element inside the viewport with an 8px gutter.
- **Reactivity:** uses `autoUpdate(anchor, node, update)` to reposition on scroll/resize/layout change; returns `update(opts)` and `destroy()` (tears down `autoUpdate`).
- **Dependency:** `@floating-ui/dom`.

### 5.2 CalBlock edit popover
- Capture the `.cal-block` element via `bind:this` as the anchor.
- The `.block-popover` element uses `use:anchored={{ anchor: blockEl, placement: 'bottom-start', gutter: 6 }}`.
- Remove the static `top: calc(100% + 6px); left: 0` from `.block-popover` CSS; the action sets `position: fixed` + computed `left`/`top`. Keep the rest of the popover styling (min-width, background, etc.). `z-index` stays high so it sits above the grid.

### 5.3 Create `BlockPopover`
- In `WeekGrid.svelte`, the create popover is wrapped in `<div style="position:absolute; top:{pendingBlock.top}px; left:0; width:240px">`. Replace the static positioning: anchor the `BlockPopover` to the pending-block ghost element (the `.ghost-block.pending` at `pendingBlock.top`) via `use:anchored`. Remove the inline `left: 0; width: 240px` positioning (keep an explicit width on the popover itself if needed for layout).
- The existing `.popover-backdrop` (`fixed; inset:0`) inside `BlockPopover` is unaffected.

### 5.4 Audit outcome (no code)
ConfirmDialog, MoreDrawer, Toaster, QuickLog, ScoreForm: verified not trigger-anchored (centered modals / fixed overlays / native controls). No clipping bug; no change. Recorded here so the audit isn't re-run.

## 6. Testing
The action is DOM/layout-bound (like `draggable.ts`), so verification is **browser / mobile-emulation**, not unit tests:
- Open the **edit popover** on blocks in the **first and last day columns**, and near the **top and bottom** of the grid, on desktop and phone → it stays fully on-screen (flips up when low, shifts left near the right edge), with the 8px gutter.
- Open the **create popover** by drag/long-press in the **last day column** and near the **bottom** → stays on-screen.
- Desktop regression: popovers still appear adjacent to their block in the common (non-edge) case.
